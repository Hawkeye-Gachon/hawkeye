Hawkeye는 운전자의 졸음과 전방 주시 이탈을 감지하면 차량이 직접 음성·공조·조명으로 운전자를 깨우고, 진행 방향의 쉼터를 내비 경유지로 넣어 실제 휴식까지 이어 주는 차량용 앱입니다.

## 왜 만들었나

**졸음은 고속도로에서 가장 많은 목숨을 앗아 갑니다.**

- 2026년 상반기 고속도로 사망자 95명 가운데 71.6%인 68명이 졸음과 주시태만으로 숨졌습니다(한국도로공사).
- 졸음운전 사고의 치사율은 음주운전 사고의 약 2배입니다(경찰청, 2019~2023년).
- 시속 100km에서 3초만 졸아도 차는 83m를 운전자 없이 달립니다.

**경고는 이미 있습니다. 문제는 그다음입니다.**

졸음을 감지해 경고하는 기술은 표준이 되어 가고 있습니다. 하지만 경고가 울린 뒤의 행동은 졸린 운전자가 스스로 정해야 합니다. 졸다가 사고를 내는 운전자는 대개 졸음이 쌓이는 것을 느끼면서도 버티며 운전을 이어 갑니다(Horne & Reyner, 1999). 쉬기로 마음먹어도 내비에서 쉼터를 찾아 경유지로 넣으려면 주행 중에 화면을 조작해야 하고, 쉼터에 닿기까지의 시간도 위험합니다. 고속도로 휴게소의 평균 간격은 약 27km입니다.

**쉬게 하면 사고는 줄어듭니다.**

졸음쉼터를 설치한 구간에서는 졸음운전 사고가 28%, 사망자가 55% 줄었습니다. 창문을 열거나 라디오를 켜는 방법은 효과가 잠깐뿐이고, 확실한 해결은 멈춰서 쉬는 것입니다(Horne & Reyner, 1999).

그래서 Hawkeye는 경고에서 멈추지 않고 **깨우기 → 쉼터 찾기 → 경로 변경 → 도착까지 버티기 → 휴식**을 대신합니다. 이 과정을 화면 조작 없이 이으려면 차량의 마이크·스피커·내비·공조를 함께 움직여야 하므로, 휴대폰 앱이 아니라 차량 앱이어야 합니다.

## 어떻게 동작하나

졸음 감지부터 쉼터에서 쉬는 순간까지를 한 단계씩 순서대로 처리하고, 운전자는 화면을 누르지 않고 말로만 응답합니다. 앞 단계가 끝난 뒤에만 다음 단계로 넘어가므로 음성 안내와 질문이 서로 겹치지 않습니다.

| 단계 | Hawkeye가 하는 일 |
| --- | --- |
| **감지** | 운전자 카메라 영상에서 눈 감김과 머리 방향을 분석합니다. 출발 후 약 1분 동안 운전자의 평소 상태를 익혀 자세와 눈 크기 차이를 보정합니다. 전방에서 3초 이상 벗어나면 전방 주시 이탈로, 눈이 감긴 비율과 지속 시간이 늘어나면 졸음으로 판단합니다. |
| **깨우기** | 전방 주시 이탈이면 음성 안내와 함께 무드등을 주황으로 바꿉니다. 졸음이면 무드등을 빨강으로, 에어컨을 18°C·바람 최대로 켜고 바깥 공기를 들입니다. 반복되면 운전석 창문을 20% 열고 시트 통풍을 켭니다. |
| **반응 확인** | 졸음 경고 뒤에도 5초 동안 눈을 뜨지 않으면 경고음과 함께 "괜찮으세요?"라고 묻습니다. 10초 동안 반응이 없으면 119가 입력된 전화 화면과 현재 위치를 띄웁니다. |
| **쉼터 경유지 추가** | 진행 방향에서 바로 들어갈 수 있는 가장 가까운 휴게소나 졸음쉼터를 찾아 경유지로 추가할지 묻습니다. "응"이라고 답하면 차량 내비에 바로 들어갑니다. 거절하면 강요하지 않습니다. |
| **도착까지 깨어 있기** | 쉼터로 가는 동안 운전 상식 O/X 퀴즈를 음성으로 냅니다. 바로 답할 수 있는 한 문장 문제입니다. |
| **휴식** | 쉼터 300m 안에서 차가 멈추면 도착으로 판단합니다. 실내를 23°C·약한 바람으로 맞추고, 기어가 P단이면 운전석 등받이를 눕힙니다. 다시 출발하면 바꾼 설정을 모두 되돌립니다. |
| **기록** | 주행이 끝나면 경로 위에 감지 위치와 들른 쉼터를 보여 주고, 일간·주간 통계로 쌓습니다. |

신호 대기 중의 오경보를 막기 위해 저속에서는 경고하지 않습니다(전방 주시·눈 감김은 시속 20km 미만, 졸음은 시속 50km 미만).

## 차량이어서 가능한 것

1. **차량이 대응의 주체입니다.** 앱이 무드등, 공조, 창문, 시트, 스피커, 내비를 한 흐름 안에서 움직입니다. 휴대폰 앱은 차량 실내 환경도, 내장 내비의 경로도 바꿀 수 없습니다.
2. **주행 중 화면 조작이 없습니다.** 경고, 질문, 대답, 퀴즈가 모두 음성으로 이루어지고, 경유지는 내비 연동으로 바로 들어갑니다.
3. **차를 원래대로 돌려놓습니다.** 조작하기 전의 설정을 읽어 두었다가 휴식이나 주행 종료 때 그대로 되돌립니다. 차종이 지원하지 않는 조작은 건너뛰고, 실제로 반영된 조치만 화면에 보여 줍니다.

운전자 영상은 기기 안에서만 처리하고 저장하지 않습니다. 쉼터 조회에는 현재 위치와 진행 방향만 서버로 보냅니다.

## 누가 어떻게 쓰나

주 사용자는 고속도로를 자주, 오래 달리는 운전자입니다.

- **오후에 이동하는 중장년 운전자.** 점심 뒤 출장길에 눈이 감기기 시작하면 무드등이 빨갛게 바뀌고 시원한 바깥 공기가 들어옵니다. "안성휴게소를 경유지로 추가할까요?"에 "응"이라고 답하면 내비에 휴게소가 들어가고, 가는 동안 O/X 퀴즈에 답합니다. 휴게소에 주차하면 실내 온도가 맞춰지고 등받이가 눕습니다.
- **새벽에 출발하는 청년 운전자.** 경고 뒤에도 눈이 5초 동안 감겨 있으면 "괜찮으세요?"라고 묻습니다. "괜찮아"라고 답하면 119 확인은 취소되고 쉼터 제안으로 넘어갑니다. 끝내 대답이 없으면 10초 뒤 119 전화 화면과 현재 위치를 띄웁니다.
- **업무로 매일 장거리를 달리는 운전자.** 주간 통계에서 졸음이 몰리는 요일과 시간대를 확인하고, 그 전에 미리 쉬어 가도록 일정을 바꿉니다.

세 경우 모두 운전자가 하는 일은 질문에 말로 대답하는 것뿐입니다. 깨우고, 쉼터를 찾고, 경로를 바꾸고, 쉴 자리를 만드는 일은 차량과 앱이 맡습니다.

## Pleos Connect SDK 활용

| SDK | 버전 | Hawkeye에서 하는 일 |
| --- | --- | --- |
| **NaviHelper** | 3.0.5 | 안내 상태·목적지·경유지를 조회하고 상태에 따라 다르게 처리합니다. 안내 중이면 쉼터를 경유지로 추가하고, 기존 경유지가 있으면 쉼터를 먼저 들르도록 경로를 다시 요청하며, 목적지가 없으면 쉼터로 길 안내를 시작합니다. |
| **Vehicle** | 2.3.2 | 공조(냉방, 외기 유입), 무드등 색, 운전석 창문, 시트 통풍을 단계별로 조작합니다. 휴식 때는 기어가 P단인지 확인한 뒤 등받이를 눕힙니다. 조작 전 값을 읽어 두었다가 복원합니다. |
| **TextToSpeech** | 3.3.1 | 경고, 반응 확인, 쉼터 질문, 퀴즈를 차량 스피커로 안내합니다. |
| **SpeechToText** | 3.3.1 | 대답을 인식해 긍정·부정과 O·X를 판단합니다. 말하기와 듣기는 한 번에 하나씩 처리해 안내 음성을 대답으로 잘못 듣지 않습니다. |
| **FusedLocation** | 1.1.3 | 차량 위치로 쉼터를 조회하고, 쉼터 300m 안에서의 정차를 도착으로 판단하며, 119 확인 화면에 현재 위치를 표시합니다. |

Pleos 차량이 아닌 기기에서는 차량 조작을 건너뛰고 Android 기본 음성과 위치로 동작합니다. 연동 코드는 [`app/app/src/main/java/com/personal/driverguard/platform/pleos/`](app/app/src/main/java/com/personal/driverguard/platform/pleos)에 있습니다.

## 구성

```text
카메라 ─▶ 얼굴 랜드마크(MediaPipe) ─▶ 졸음 판정(ai) ─▶ 앱(app) ─┬─▶ 차량: 음성·조명·공조·창문·시트·내비 (Pleos SDK)
                 기기 안에서 처리                              └─▶ 서버(backend): 쉼터 조회, 계정, 주행 기록
```

| 폴더 | 내용 |
| --- | --- |
| [`app/`](app) | Android 앱. Kotlin, Jetpack Compose, minSdk 28 / targetSdk 36. 카메라 프레임을 약 15fps로 MediaPipe 얼굴 랜드마크 모델에 넣고 졸음 판정 라이브러리로 판단합니다. |
| [`ai/`](ai) | 졸음 판정 라이브러리와 학습 파이프라인. 설계 명세(`ai/docs/SPEC.md`), 앱용 Kotlin 이식본(`ai/kotlin/`). Python 학습 코드와 같은 계산 명세로 구현해 학습 환경과 차량에서 같은 결과가 나옵니다. |
| [`backend/`](backend) | 쉼터 조회와 계정, 주행 기록 서버. Spring Boot, PostgreSQL. 졸음쉼터 표준데이터와 휴게소 정보를 바탕으로, 지금 달리는 방향에서 실제로 들어갈 수 있는 가장 가까운 한 곳을 고릅니다. |
| [`design/`](design) | 전체 화면 시안(`design/hawkeye_design.fig`)과 디자인 원칙 |
| [`apk/`](apk) | Android 앱 설치 파일 |

[릴리즈 페이지](https://github.com/Hawkeye-Gachon/hawkeye/releases/latest)나 [`apk/`](apk) 폴더에서 APK를 받습니다.

## 개발 현황

### 구현한 것

- 감지: 카메라 → MediaPipe → 규칙 기반 판정(눈 감김 비율, 감김 지속 시간, 3초 이상 시선 이탈). 개인 기준 보정과 저속 경고 억제.
- 감지 이후 흐름: 경고와 단계별 실내 조치 → 반응 확인(119 전화 화면) → 쉼터 음성 질문 → 경유지 추가 → 음성 O/X 퀴즈 → 도착 판정과 휴식 모드 → 설정 복원.
- 위 SDK 호출 코드와 내비 상태별 처리, 서버의 쉼터 조회·주행 기록·리포트와 일간·주간 통계.
- 단위 테스트와 화면 스냅숏 테스트.


### 앞으로 할 것

1. Pleos Connect 에뮬레이터와 실차에서 SDK 동작을 검증하고 차량 제어 권한 범위를 확인합니다.
2. 실내 카메라를 쓸 수 없는 차량을 위해 연속 주행 시간과 음성 확인 질문으로 동작하는 대체 경로를 만듭니다.
3. 규칙 기반 판정에 학습된 졸음 모델(ONNX, 기기 내 실행)을 더합니다.
4. 퀴즈에 경로상 지역 문제와 끝말잇기를 추가하고, 대답이 느려지면 더 가까운 쉼터를 다시 제안합니다.
5. 방향지시등이 켜지면 퀴즈를 멈춥니다.
6. 음성 인식·합성을 온디바이스로 바꾸고 쉼터 목록을 앱에 내장해, 통신이 끊긴 구간에서도 동작하게 합니다.
7. 가로 고정인 화면을 세로 창에서도 쓸 수 있게 합니다.

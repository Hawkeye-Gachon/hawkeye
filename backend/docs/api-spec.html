공통 사항

Base URL로컬 http://localhost:8080
Content-Typeapplication/json (요청·응답 모두 UTF-8)
인증/api/auth/** 를 제외한 모든 API 는 헤더 필요:
Authorization: Bearer {accessToken}
토큰 유효기간accessToken 30분 · refreshToken 14일 (재발급 시 refreshToken 도 새로 바뀜)
시간 형식ISO-8601 (예: 2026-11-06T16:40:39.765+09:00)
accessToken 이 만료되면 401 → /api/auth/refresh 로 재발급 후 다시 호출하세요.

에러 응답

토큰 없음 / 잘못된 토큰 / 만료 (인증 필요한 API) → 401

{ "code": "UNAUTHORIZED", "message": "인증이 필요합니다." }

그 밖의 에러 (400 입력값 오류, 401 로그인 실패, 404, 409 등)

{
  "timestamp": "2026-11-06T07:33:28.287Z",
  "status": 409,
  "error": "Conflict",
  "message": "이미 사용 중인 이메일입니다.",
  "path": "/api/auth/signup"
}

입력값 검증 실패(400)의 message 는 "Validation failed for object='...'. Error count: N" 형식이며 필드별 상세는 포함되지 않습니다.

RestPlace

POST/api/rest-places/nearbyBearer 필요

가장 가까운 휴게소/졸음쉼터 조회

졸음 감지 시 호출합니다. 현재 위치·진행 방향 기준으로 지금 차선에서 바로 들어갈 수 있는 곳(반대 차선 제외) 중 카카오 길찾기 기준 실제 도로 거리가 가장 가까운 1곳을 돌려줍니다. 앱은 place 의 위도·경도를 경유지로 추가하면 됩니다.

고속도로 전용입니다. 일반도로에서는 onHighway=false, place=null 을 반환합니다.

Request Body

필드타입필수설명
latnumberO현재 위도 (-90 ~ 90)
lngnumberO현재 경도 (-180 ~ 180)
headingnumber진행 방향 0~360° (북쪽 0, 시계 방향). Android Location.getBearing()
speednumber속도 m/s (0 이상). Android Location.getSpeed(). speed ≥ 2.8(약 10km/h)일 때만 heading 을 반영
typestringREST_AREA / DROWSY_SHELTER. 생략하면 둘 다
{ "lat": 37.073253, "lng": 127.132555, "heading": 340, "speed": 27 }
heading·speed 를 보내지 않으면 진행 방향을 알 수 없어 정확도가 떨어집니다. 주행 중에는 항상 함께 보내세요.

Response 200 OK — 고속도로 위 (경부고속도로 서울 방향, 오산 부근 실제 호출)

{
  "directionApplied": true,
  "onHighway": true,
  "distanceSource": "ROAD",
  "place": {
    "placeId": 1211,
    "type": "DROWSY_SHELTER",
    "name": "오산",
    "latitude": 37.1542659,
    "longitude": 127.0861027,
    "roadDistanceMeters": 10313,
    "durationSeconds": 689
  }
}

Response 200 OK — 일반도로 (서울 강남대로 실제 호출)

{ "directionApplied": true, "onHighway": false, "distanceSource": "ROAD", "place": null }

응답 필드

필드타입설명
directionAppliedboolean진행 방향을 반영했는지 (저속이거나 heading 없으면 false)
onHighwayboolean | nulltrue 고속도로 위 · false 일반도로(안내 안 함) · null 확인 못함(근처에 휴게소 없음 / 길찾기 실패)
distanceSourcestringROAD 카카오 길찾기로 확인한 결과 · UNAVAILABLE 길찾기 실패로 확인 불가 (place=null)
placeobject | null가장 가까운 쉴 곳. 없으면 null
place.placeIdnumber장소 ID
place.typestringREST_AREA(휴게소) / DROWSY_SHELTER(졸음쉼터)
place.namestring이름 (예: 죽전(서울)휴게소, 오산)
place.latitudenumber위도 — 경유지 좌표
place.longitudenumber경도 — 경유지 좌표
place.roadDistanceMetersnumber앞으로 가야 하는 실제 도로 거리 (m, 카카오 길찾기 기준)
place.durationSecondsnumber예상 소요 시간 (초, 교통 상황 반영)

앱 처리 가이드

응답앱 동작
place 있음해당 좌표를 경유지로 추가하고 이름·거리 안내
onHighway=false일반 안내 (예: "안전한 곳에 정차해 휴식하세요")
distanceSource=UNAVAILABLE일반 안내 (일시적 길찾기 실패 — 잠시 후 재요청 가능)
onHighway=true 인데 place=null앞쪽에 확인된 쉴 곳 없음 → 일반 안내

에러

상태상황
400lat/lng 누락, 좌표·heading 범위 오류, speed 음수
401토큰 없음/만료

동작 방식 (참고)

  • DB 의 고속도로 휴게소(도로공사)·졸음쉼터(공공데이터포털) 중 반경 50km, 진행 방향 앞쪽 후보를 추린 뒤 그 후보들만 카카오 길찾기로 확인합니다 (요청 1건당 길찾기 약 4~16회).
  • 경로 모양(지나쳤다가 되돌아옴, 반대 방향으로 도착 등)으로 반대 차선 휴게소를 제외하고, 졸음쉼터는 내 방향으로 확인된 경로 위에 있는 곳만 인정합니다.
  • 확신할 수 없는 곳은 제외하는 방식이라, 진입로가 복잡한 일부 휴게소(예: 행담도)는 내 방향이어도 나오지 않을 수 있습니다.
  • 응답 시간: 보통 0.2 ~ 1.5초.

참고: 휴게소/졸음쉼터 데이터 수집

API 가 아닌 서버 내부 작업입니다. 별도 호출은 필요 없습니다.

설정 (application.properties)설명
driverguard.rest-place.sync-enabledtrue 면 자동 수집. 없거나 false 면 수집 안 함
driverguard.rest-place.sync-cron수집 주기. 기본 0 0 4 * * MON (매주 월요일 04:00, Asia/Seoul)
  • 수집이 켜져 있고 DB 가 비어 있으면 앱 시작 직후 한 번 수집합니다.
  • 원천 API 실패 또는 0건이면 기존 데이터를 유지합니다.
  • 현재 데이터: 졸음쉼터 253곳 + 휴게소 203곳.

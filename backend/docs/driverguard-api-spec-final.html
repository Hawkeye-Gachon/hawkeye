개요

졸음·부주의 판정, 정면 방향 설정, 경고 표시, 차량 내비(NaviHelper) 연동은 앱에서 처리하고, 서버는 회원·약관 관리, 쉼터 찾기, 주행 기록 저장과 리포트 집계를 맡습니다. 관찰 중 서버 호출은 졸음·부주의 3회 누적 시 쉼터 찾기 한 번뿐이고, 감지·경로·경유지 기록은 관찰을 마칠 때 한 번에 올립니다.

에러 응답

모든 에러가 같은 형식입니다. 앱은 code 로 분기하고, fieldErrors 가 있으면 field 이름의 입력란 아래에 message 를 표시합니다. fieldErrors 는 입력값 오류일 때만 있습니다.

{
  "timestamp": "2026-11-06T11:43:17.913901200Z",
  "status": 400,
  "error": "Bad Request",
  "code": "VALIDATION_FAILED",
  "message": "입력값을 확인해 주세요.",
  "path": "/api/auth/signup",
  "fieldErrors": [
    { "field": "ageConfirmed", "message": "만 14세 이상만 가입할 수 있습니다." },
    { "field": "email", "message": "이메일 형식이 아닙니다. 예: name@mail.com" },
    { "field": "name", "message": "이름을 입력해 주세요." },
    { "field": "password", "message": "비밀번호는 영문과 숫자를 섞어 8~64자로 입력해 주세요." }
  ]
}

JSON 값 형식이 틀리면(없는 enum 값, 시간대 없는 시각 등) field 에 위치가 들어갑니다. 예: {"field": "events[0].type", "message": "값의 형식이 올바르지 않습니다."}. JSON 문법 자체가 틀리면 fieldErrors 없이 400.

졸음 감지 즉시(부주의 3회 누적이면 정면 주시 확인 후) 호출합니다. 현재 위치·진행 방향 기준으로 지금 차선에서 바로 들어갈 수 있는 곳(반대 차선 제외) 중 카카오 길찾기 기준 실제 도로 거리가 가장 가까운 1곳을 돌려줍니다. 앱은 place 의 좌표를 NaviHelper 경유지(목적지가 없으면 목적지)로 추가하고, 제안 화면에 type 과 roadDistanceMeters 를 "졸음쉼터 · 전방 10.3km" 처럼 표시합니다.

판정 방식 (틀린 곳을 안내하지 않는 것이 원칙)

  • 휴게소: 카카오 길찾기를 진행 방향으로 출발시켜 경로 모양을 봅니다. 휴게소를 지나쳤다가 되돌아와 도착하면 반대 차선으로 제외합니다.
  • 졸음쉼터: 카카오 지도에 진입로가 없어, 내 방향으로 확인된 휴게소까지의 경로 위(60m 이내)에 있고 방향 표기가 같은 쉼터만 인정합니다.
  • 서울외곽순환: 같은 "일산 방향"이라도 원의 위치에 따라 회전이 바뀌어, 차의 회전(시계·반시계)과 장소의 회전을 좌표로 비교합니다. 방향을 알 수 없는 장소는 제외합니다.
  • 확인되지 않으면 결과를 비웁니다. 검증: 고속도로 12개 방향(15km 간격)과 서울외곽순환 양방향 실주행 시나리오에서 반대 차선 0건, 오프라인 회귀 테스트 78개.

한 번 호출에 카카오 길찾기가 8~24회 나가며 응답까지 보통 1~3초 걸립니다. 경고음·빨간 화면은 이 응답을 기다리지 말고 즉시 표시합니다.

화면별 호출 순서

페이지별 가이드의 화면 흐름마다 호출하는 API 입니다. 각 단계의 실제 요청·응답은 docs/api-test-run.md 에 있습니다.

상황순서
1. 처음 가입POST /api/auth/signup (토큰 저장) → GET /api/terms → 전문 보기 GET /api/terms/{id} → 동의하고 시작하기 POST /api/users/me/terms-agreements → 홈 GET /api/drives?size=1, GET /api/reports/weekly?weekStart=이번 주 월요일
2. 로그인POST /api/auth/login → termsAgreementRequired true 면 약관 화면(GET /api/users/me/terms-agreements 로 이전 선택 채움), false 면 홈. 사용 중 403 TERMS_AGREEMENT_REQUIRED 를 받아도 약관 화면. 401 이면 POST /api/auth/refresh 후 재시도
3. 관찰 시작정면 방향 설정은 앱 처리 → POST /api/drives (clientDriveId·시작 시각을 먼저 로컬 저장, 실패해도 관찰은 시작하고 재시도) → 관찰 중 경과 시간·횟수는 앱이 셈
4. 전방 주시 이탈앱 처리 (경고 표시, 감지 시각·위치 로컬 저장)
5. 졸음 감지경고음·빨간 화면 즉시 → 동시에 POST /api/rest-places/nearby → place 있으면 경유지 추가 제안, 없으면 일반 정차 안내 → NaviHelper 성공 콜백이면 경유지 기록 로컬 저장
6. 부주의 3회 누적정면 주시 확인 후 POST /api/rest-places/nearby → 이후 5와 같음 (trigger=INATTENTION_REPEATED)
7. 관찰 종료POST /api/drives/{id}/end → 응답으로 바로 리포트 표시, 200 후 로컬 기록 삭제 → 홈으로 GET /api/drives?size=1
8. 업로드 못 한 주행앱 실행 시 로컬에 남은 주행 확인 → driveId 가 없으면 POST /api/drives (저장해 둔 clientDriveId·시작 시각) → POST /api/drives/{id}/end (종료 시각이 없으면 마지막 기록 시각)
9. 지난 기록GET /api/reports/daily (date 생략) → 달력 GET /api/reports/calendar?month= → 날짜 이동 daily?date= → 주행 항목 GET /api/drives/{id} → 주간 탭 GET /api/reports/weekly → 요일 막대 daily?date=
10. 회원 탈퇴DELETE /api/users/me → 204 면 앱의 토큰·로컬 데이터 삭제 후 로그인 화면

DB 테이블

PostgreSQL. 전체 정의는 src/main/resources/db/schema.sql. 테이블은 복수형, PK 는 테이블_id, 시각은 TIMESTAMPTZ, 제약조건은 pk_/fk_/uq_/ck_/ix_ 접두어, 상태값은 CHECK 제약을 씁니다.

테이블용도주요 제약
users사용자 (이메일, 이름, 상태, 만 14세 확인 시각, 탈퇴 시각)이메일 유니크는 ACTIVE 사용자에게만 (탈퇴 후 재가입 가능)
auths인증 수단 (EMAIL: 비밀번호 해시). 소셜 로그인 확장 가능(user_id, provider) 유니크
refresh_tokens로그인(기기) 1건당 1행, SHA-256 해시만 저장token_hash 유니크
terms약관 버전별 1행 (전문 마크다운, 필수 여부, 표시 순서, 시행 시각)(code, version) 유니크
user_terms_agreements사용자 × 약관 버전별 동의 기록(user_id, terms_id) 유니크, 동의면 동의 시각 필수
rest_places휴게소 + 졸음쉼터 (주 1회 공공데이터 수집, 없어진 곳은 비활성)(place_type, source_key) 유니크
drives관찰 1회 + 종료 때 계산한 요약값 + 단순화 경로(JSONB)(user_id, client_drive_id) 유니크, 사용자당 IN_PROGRESS 1개(부분 유니크 인덱스)
drive_events부주의·졸음 감지 1건(drive_id, event_type, detected_at) 유니크
drive_waypoints쉼터 경유지 추가 기록 (장소 정보 스냅샷, 방문 여부)방문이면 방문 시각 필수
drive_hourly_stats주행 × 서울 기준 1시간 구간 집계 (리포트 전용)(drive_id, hour_start) 유니크

주행 하위 테이블은 모두 ON DELETE CASCADE 라, 탈퇴 때 주행만 지우면 감지·경유지·통계가 함께 지워집니다.
